## Why

Отдельные роли делегирования (worker/scout/researcher/reviewer) на одном наборе
моделей и два точечных исключения из полного блока мутирующих тулов лида (F19; третье — amendment FR-007, Approved 2026-11-02 11:45, см. ниже):
штатные `write`/`edit` внутри realpath-цели `openspec/` проекта (она может быть
вне корня проекта) и доверительный полнофункциональный `perl` через `bash` для
документации в этой цели.

## What Changes

- Четыре ролевых профиля агентов на базе pi-subagents, роль по умолчанию —
  `worker` (совместимость существующих вызовов); модель по роли отдельно не
  выбирается.
- Ролевые наборы инструментов и схемы отчётов; честное сообщение о недоступных
  веб-инструментах вместо выдачи догадок за исследование.
- Исключения в lead-гейте с явной рамкой «проверяемая граница, а не песочница»
  (произвольный Perl и reviewer с bash не дают изоляции ФС).
- *(Amendment rev.4 — утверждён владельцем 2026-11-02 11:45; до утверждения прошли ревью-циклы, см. статус-блок)* Третье точечное
  исключение из lead-гейта: одиночные команды bd трекера (`create`, `show`,
  `list`, `ready`, `update`, `close`) через `bash` — лид сам заводит и ведёт
  задачи bd; воркеры трекер по-прежнему не ведут.
- *(Amendment-ЧЕРНОВИК)* Три ужесточения perl-пути относительно rev.3 (полный перечень; поведенческие изменения): (1) разделители слов — только пробел и табуляция, а `\v`, `\f`, NBSP — обычные символы слова (design §6.1.7); (2) неквотированный `#` вне кавычек отказывается (см. пункт B-NEW ниже); (3) каталог настроек и fail-closed (см. пункт о каталоге настроек ниже).
- *(Amendment-ЧЕРНОВИК, B-NEW)* Ужесточение общего токенайзера: неквотированный `#` вне кавычек отклоняется и для одиночного perl (поведенческое изменение к rev.3: хвостовой комментарий `perl -e 'x' # …` больше не разрешается), и для bd. Закрывает обход «ровно один вызов» через `#`-комментарий bash (`perl -e 'print 1' #'` + перевод строки + вторая команда).
- *(Amendment-ЧЕРНОВИК, design §6.6, tasks §9)* Каталог настроек для perl- и bd-исключений — реплика `getAgentDir` хоста (без `HOME`-приоритета rev.3); дополнительные кандидаты `HOME`/`USERPROFILE` и проектный файл `projectRoot/.pi/settings.json` проверяются по fail-closed-правилу; неразрешимый каталог — отказ исключения. Поведенческое изменение к rev.3 (третье ужесточение perl-пути).

## Out of Scope

- Рекурсивное делегирование детьми; отдельная модель на роль; автоматический
  конвейер зависимостей; замена Perl специализированным инструментом замены;
  заявления об изоляции файловой системы.
- Изоляция или проверка полномочий/подлинности bd: аргументы и настройки bd
  могут иметь побочные эффекты, бинарник резолвится оболочкой через PATH
  (риски — design §6.5.7).
- Подкоманды bd сверх `create|show|list|ready|update|close` (например,
  `dolt push`, `remember`, `prime`) — только новым amendment. `bd init` лиду в
  рамках этого amendment не разрешается: инициализация выполняется только тестовым
  harness (tasks 8.8). Решения о будущих amendments этим документом не принимаются. Побочное создание базы bd по пути из разрешённого на доверии `--db` (OQ-6) не исключается гейтом и не проверено (FR-007).
- Ограничение флагов `--db`/`--global` не входит в объём: решение владельца OQ-6 (2026-11-02; дословно, через goal_question: «Разрешить оба флага на доверии; лид сможет выбирать и другие трекеры») — разрешены на доверии, это не изоляция. Гипотетические флаги bd для чтения файлов, редактора и hook допускаются на доверии по решению владельца OQ-8 (2026-11-02; дословно: «Разрешить на доверии, как остальные аргументы bd»); их наличие и эффекты не проверены и не утверждаются (design §6.5.7).
