# FX1: выводы красного и зелёного прогонов 9.4-B / 9.4-D (приложено)

## Что здесь

- `9.4-B-red-repro.txt` — красный прогон: код rev.3 (HEAD `4d95952`, до фикса §6.6) + новый
  `test/restrictions.test.ts`. Итог: **122 теста, 80 провалено, exit 1**. Среди проваленных —
  целевые кейсы §6.6: `resolves the host agent dir from USERPROFILE and disables the perl
  exception (9.4-B)`, вся группа `host agent dir parity (design §6.6 rule 1, tasks 9.3)` и
  win32-кейсы `HOME never decides`, `/c/… maps to a drive path`.
- `9.4-D-green.txt` — зелёный прогон: текущее дерево после фикса. Итог: **Test Files 21 passed,
  Tests 646 passed, exit 0** (полный набор, не только restrictions).

## Честная атрибуция

- Исходный «красный до фикса» (7 падающих в момент фикса, отчёт воркера) исполнялся на
  промежуточном состоянии — швы (9.1) уже были добавлены, поведение (9.2) ещё нет; этот прогон
  не сохранил вывод, что и породило находку FX1.
- Воспроизведение здесь использует более раннюю точку (чистый rev.3/HEAD + новые тесты): оно
  строго краснее (80 падающих против 7) и доказывает то же самое — новые §6.6-тесты не проходят
  против кода до фикса и проходят после. Порядок «красный до фикса, зелёный после» подтверждён
  репродукцией post-factum: грин прогонялся на дереве, где фикс уже существует; красный — на
  git-worktree HEAD без правок.
- Команды: `git worktree add D:/tmp/fx1-red HEAD` + копия нового тест-файла →
  `npx vitest run test/restrictions.test.ts` (красный); в основном дереве →
  `npx vitest run` (зелёный). Worktree удалён после прогона.
