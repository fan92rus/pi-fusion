# Spec Delta

## Purpose

Послойная конфигурация fusion: проектный файл `.pi/fusion.json` переопределяет
поля глобального `~/.pi/agent/fusion.json` на уровне отдельных полей; цель
записи выбирается переключателем внутри `/fusion config`; происхождение
каждого значения видно оператору. Существует, чтобы настройки можно было
закреплять за проектом (в т.ч. класть в git), не ломая глобальные для других
проектов.

## ADDED Requirements

### Requirement: Проектный файл конфигурации

Система MUST поддерживать проектный файл конфигурации fusion по пути
`.pi/fusion.json` относительно корневого каталога проекта (рабочего каталога
сессии). Файл использует ту же форму полей, что и глобальный
`~/.pi/agent/fusion.json`. Поля, отсутствующие или невалидные в проектном
файле, MUST обрабатываться как «не переопределены» — чтение не падает и не
предупреждает об отсутствии файла (отсутствие проектного файла = конфигурация
целиком глобальная).

#### Scenario: Файл существует и валиден

- **WHEN** в рабочем каталоге есть `.pi/fusion.json` с `"workers": 8`
- **THEN** эффективная конфигурация содержит `workers: 8`, а остальные поля —
  из глобального файла или дизайн-дефолтов

#### Scenario: Файла нет

- **WHEN** в рабочем каталоге нет `.pi/fusion.json`
- **THEN** эффективная конфигурация полностью совпадает с глобальной, как
  если бы слоёв не было

#### Scenario: Битый JSON

- **WHEN** `.pi/fusion.json` существует, но не парсится как JSON
- **THEN** файл игнорируется целиком (эффективная конфигурация глобальная),
  и выводится предупреждение оператору

### Requirement: Наложение полей без суммирования

Эффективное значение каждого поля MUST вычисляться независимо: значение из
проектного файла заменяет глобальное, если задано и валидно; иначе действует
глобальное; иначе — дизайн-дефолт. Списковые поля (`workerModels`,
`blockedTools`, `leadBlockedTools`) MUST заменяться целиком — локальный список
заменяет глобальный, объединения и суммирования нет (решение владельца
2026-11-05). Ни одно поле MUST NOT суммироваться, мёржиться или иначе
комбинироваться из двух слоёв.

#### Scenario: Локальные модели заменяют глобальные

- **WHEN** глобальный `workerModels = [A, B]`, проектный `workerModels = [C]`
- **THEN** эффективный список моделей — `[C]`, не `[A, B, C]`

#### Scenario: Локальные блокировки заменяют глобальные

- **WHEN** глобальный `leadBlockedTools = [write, edit, bash, subagent]`,
  проектный `leadBlockedTools = [write, edit]`
- **THEN** эффективный список — `[write, edit]`: проектный список заменяет
  глобальный, а не расширяет его

#### Scenario: Частичное переопределение

- **WHEN** проектный файл задаёт только `taskTimeoutMs`
- **THEN** все остальные поля берутся из глобального файла без изменений

### Requirement: Переключатель конфигурации в /fusion config

Интерактивное меню `/fusion config` MUST предоставлять переключатель между
двумя конфигурациями: global (`~/.pi/agent/fusion.json`) и local
(`.pi/fusion.json` проекта). Выбранная конфигурация определяет, какой файл
читают и правят экраны меню. Переключение само по себе MUST NOT менять
содержимое файлов.

#### Scenario: Выбор local-режима

- **WHEN** оператор открывает `/fusion config` и выбирает конфигурацию local
- **THEN** последующие экраны меню показывают и правят локальный слой:
  локальные переопределения и наследуемые значения

#### Scenario: Переключение ничего не пишет

- **WHEN** оператор переключается global → local и выходит без правок
- **THEN** ни один файл конфигурации не изменяется

### Requirement: Local-режим меню — происхождение и дельта-запись

В local-режиме меню MUST показывать происхождение каждого поля (local /
global / default) и сохранять каждую правку немедленно дельтой только
изменённого поля. Наследуемое поле (источник global/default) правится
только через явный шаг «переопределить здесь» (confirm), который и создаёт
переопределение; сброс переопределения удаляет локальный ключ (опустевший
файл удаляется).

#### Scenario: Просмотр локального слоя

- **WHEN** local-режим открыт, а `.pi/fusion.json` переопределяет только
  `workers`
- **THEN** `workers` показан с источником local, остальные поля — с их
  фактическим источником (global или default)

#### Scenario: Правка локального слоя пишет дельту немедленно

- **WHEN** оператор в local-режиме меняет `workers` на 8 и подтверждает
  ввод
- **THEN** `.pi/fusion.json` сразу после правки содержит поле `workers` со
  значением 8; поля, которых оператор не менял, в файл не пишутся

#### Scenario: Подтверждение нового переопределения

- **WHEN** оператор в local-режиме начинает правку поля с источником
  global/default
- **THEN** меню явно спрашивает подтверждение «переопределить здесь», и
  только после него создаётся локальное переопределение

#### Scenario: Сброс переопределения

- **WHEN** оператор сбрасывает единственное локальное переопределение
  (`workers`) к наследованию
- **THEN** ключ `workers` удаляется из `.pi/fusion.json`, поле наследуется
  из глобального слоя, а опустевший файл удаляется

### Requirement: Запись в битый локальный файл отказывает

Если `.pi/fusion.json` существует, но непарсится как JSON или не является
JSON-объектом (массив, null, скаляр), любая запись в него (правка или
сброс переопределения) MUST отказывать с понятной оператору ошибкой (путь
и причина), не перезаписывая файл молча. Чтение при этом уже игнорирует
файл (требование «Проектный файл конфигурации», сценарий «Битый JSON»).

#### Scenario: Отказ записи в битый файл

- **WHEN** `.pi/fusion.json` содержит невалидный JSON и оператор сохраняет
  изменение в local-режиме
- **THEN** запись отказывает с ошибкой, называющей путь и причину; файл
  остаётся нетронутым

#### Scenario: Отказ записи в не-объект

- **WHEN** `.pi/fusion.json` содержит `[]` или `"x"` и оператор сохраняет
  изменение в local-режиме
- **THEN** запись отказывает так же, как при непарсящемся JSON; файл
  остаётся нетронутым

### Requirement: Подкоманды и статус учитывают слои

Подкоманды `/fusion workers`, `/fusion model`, `/fusion timeout` MUST
применять своё изменение к эффективной конфигурации и записывать в проектный
`.pi/fusion.json`, когда он существует, иначе — в глобальный файл (правило
«пишем туда, откуда пришло»; детали — design D4); при отсутствии проектного
файла он MUST NOT создаваться ярлыком. `/fusion status` MUST показывать
для каждого поля его источник: `local`, `global` или `default` (значение
взято из дизайн-дефолтов, ни один файл его не задаёт).

#### Scenario: Ярлык пишет в существующий локальный слой

- **WHEN** `.pi/fusion.json` существует и оператор выполняет `/fusion workers 5`
- **THEN** `workers: 5` сохраняется в `.pi/fusion.json`; глобальный файл не
  меняется

#### Scenario: Ярлык пишет глобально без локального файла

- **WHEN** `.pi/fusion.json` не существует и оператор выполняет
  `/fusion model vendor/a`
- **THEN** ротация сохраняется в глобальный `~/.pi/agent/fusion.json`, а
  проектный файл НЕ создаётся

#### Scenario: Статус показывает источник

- **WHEN** `.pi/fusion.json` переопределяет `workers`, модели заданы только
  глобально, а `taskTimeoutMs` не задан нигде
- **THEN** `/fusion status` выводит `workers` с пометкой `local`, модели —
  с пометкой `global`, `taskTimeoutMs` — с пометкой `default`

### Requirement: Механика конфигурации не меняется в остальном

Форма полей, границы значений, атомарная запись (tmp+rename), поведение
«свежее чтение при каждом вызове» и сессионная активация (`/fusion on|off`,
без поля `enabled`) MUST сохраняться без изменений. Отсутствие или
невалидность проектного файла MUST NOT влиять на загрузку расширения.
Гейт лида MUST читать эффективный список `leadBlockedTools` свежо при
каждом вызове — локальное переопределение блокировок подействует без
перезапуска pi.

#### Scenario: Свежее чтение сохраняется

- **WHEN** оператор правит `.pi/fusion.json` в редакторе во время сессии
- **THEN** следующий вызов `fusion_delegate` и следующая перерисовка guidance
  используют новые значения без перезапуска

#### Scenario: Расширение грузится без проектного файла

- **WHEN** расширение загружается в проекте без `.pi/fusion.json`
- **THEN** загрузка проходит ровно как сегодня: глобальная конфигурация,
  дефолты при её отсутствии, никаких предупреждений

#### Scenario: Локальные блокировки лида подействуют без перезапуска

- **WHEN** `.pi/fusion.json` переопределяет `leadBlockedTools`, пока сессия
  с включённым fusion работает
- **THEN** следующий вызов инструмента лида проверяется уже против
  локального списка без перезапуска pi
