# Proposal: fusion-footer-status

> Status: rev.2 (раунд 1 НЕ ГОДЕН закрыт; контрольный раунд 2 — ГОДЕН, run aab38392). Автор — lead (glm-5.3-flash); ревью — кросс-модельное,
> свежим fusion-reviewer. Язык артефактов — ru (конвенция config.yaml).

## Что

Постоянный индикатор режима fusion в нижней строке TUI pi: расширение занимает
слот штатного футера через `ctx.ui.setStatus('fusion', …)` и показывает
`fusion: on` / `fusion: off` — состояние активации ТЕКУЩЕЙ сессии (модель
изменения fusion-session-activation; спека rev.4 реализована, commit ae4c14f).

## Зачем

После перехода на session-only активацию режим сессии стал невидим: новая сессия
стартует off, и владелец замечает это только по отказу делегирования. Постоянный
индикатор внизу даёт мгновенную видимость без запроса `/fusion status`.

## Как

- Обновление ровно в двух классах точек: (а) каждый `session_start` — после
  applySessionStart/реконсайла; (б) немедленно при `/fusion on` и `/fusion off`
  (включая идемпотентные повторы — текст обязан совпасть с фактическим состоянием).
- Значение — из session-state текущей сессии (та же Map/restore-семантика).
- TUI/RPC-футер: обновление пишется всегда, когда контекст предоставляет метод
  `ctx.ui.setStatus` (режимы `tui` и `rpc` с UI; режим `print`/`json` и отсутствие
  метода — тихий пропуск без ошибок, критерий — только фактическое наличие метода,
  не значение `ctx.mode`).
- Детали (source: memory/history/env/default-off, воркеры, модели) в футер НЕ
  идут — их место `/fusion status`.

## Границы

Не меняет: сессионную модель активации, гейты, конфигурацию, пул, seam, профили.
Единственные затрагиваемые файлы: index.ts (хук session_start), commands.ts
(turnFusion), тесты-пины, README (одна строка).
