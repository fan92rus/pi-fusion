# Proposal: fusion-lead-subagent-block

> Status: rev.2 (правка по решению владельца 2026-11-02: блок — через конфиг,
> как остальные блокировки). Язык артефактов — ru.

## Что

При включённом fusion нативный инструмент `subagent` попадает в блок-лист лида
`leadBlockedTools` — тот же механизм, что у write/edit/bash/powershell. Делегирование
идёт только через `fusion_delegate`. В guidance-вставку добавляется строка приоритета,
которая отменяет конфликтующие оркестрационные указания окружения (AGENTS.md §4,
скиллы subagent-orchestration*).

## Зачем

1. Единственный путь делегирования — единственная дисциплина: пул, роли, схемные
   отчёты, таймауты работают только когда всё идёт через обёртку. Нативный `subagent`
   их обходит (живьём: лид запускал ревьюеров нативно).
2. Конфликт промпта: guidance говорит «fusion_delegate», а AGENTS.md §4 и скиллы
   оркестрации учат нативному `subagent`. Строка приоритета + блок в конфиге снимают
   конфликт детерминированно.

## Как

- config.ts: `subagent` добавляется в `FUSION_CONFIG_DEFAULTS.leadBlockedTools`.
- restrictions.ts: без изменений — блок работает штатным путём блок-листа.
- guidance.ts: строка приоритета в BEHAVIOUR_LINES.
- README: одна строка.

## Важный нюанс (нужно решение владельца)

Явный список в `fusion.json` ЗАМЕЩАЕТ дефолт. В текущем файле владельца записано
`leadBlockedTools: ["write","edit","bash"]` — поэтому одно изменение дефолта на
твоей машине ничего не даст. Варианты:
- (а) владелец вручную добавляет `"subagent"` в `~/.pi/agent/fusion.json`
  (рекомендую: файл вне openspec/, лид туда писать не может, и это явный выбор);
- (б) миграция: при загрузке, если в файле есть `leadBlockedTools` без `subagent`,
  — warn + авто-добавление. Это меняет семантику «явный список замещает дефолт»
  и я бы не делал без отдельного согласия.

## Границы

Не трогаем: codemode, гейты write/edit/bash/perl/bd, пул, seam, профили, сессионную
модель, семантику замещения списка в конфиге.
