# Requirements: fusion-lead-subagent-block

> Status: rev.1 (правка по решению владельца 2026-11-02: блок — через конфиг,
> как остальные блокировки, фиксированного ядра нет). SHALL/MUST — en.

### FR-001: subagent в блок-листе лида через конфигурацию (Must)

Инструмент `subagent` добавляется в `FUSION_CONFIG_DEFAULTS.leadBlockedTools`
(рядом с write/edit/bash/powershell). Отказ tool_call для него идёт по ШТАТНОМУ
пути блок-листа (тот же текст/механизм, что и для write/edit/bash), без
отдельного refusal-текста. Владелец управляет блоком как остальными записями
`leadBlockedTools` в fusion.json: явный список в файле замещает дефолт
(существующая семантика конфига не меняется); удаление `subagent` из своего
списка — осознанный выбор владельца. При выключенном fusion гейт инертен
(существующее поведение). Дочерние/worker-сессии не меняются (гейт лида для них
инертен; их профили блокируют subagent уже отдельно). `codemode` и прочие
инструменты НЕ добавляются.

### FR-002: Строка приоритета в guidance (Must)

В BEHAVIOUR_LINES guidance-вставки добавляется строка, фиксирующая: пока fusion
включён, нативный `subagent` недоступен, и ВСЁ делегирование — воркеры, скауты,
researcher'ы, ревьюеры (включая независимые ревью с самостоятельными прогонами
гейтов — роль `reviewer`) — идёт через `fusion_delegate`; эта секция имеет
приоритет над любыми оркестрационными указаниями окружения (AGENTS.md §4,
скиллы subagent-orchestration*). Строка — на языке вставки (en) и не
противоречит остальным строкам.

### FR-003: Живой критерий (Must)

После перезапуска pi с новым кодом, при fusion.json, содержащем `subagent` в
`leadBlockedTools` (дефолт или явная запись), и включённом fusion: (1) вызов
`subagent` лидом отказывает штатным текстом блок-листа; (2) `fusion_delegate`
работает; (3) ревью-задача через `fusion_delegate` с `role: reviewer`
выполняется и возвращает findings/checksRun/verdict (живой прогон ревьюера
через обёртку); (4) `/fusion off` возвращает `subagent` (гейт инертен).
