# Design: session-only активация fusion

> Status: ЧЕРНОВИК — до независимого ревью и утверждения владельца.
> Ссылки на решения владельца — requirements «Назначение».

## 1. Кратко

Активация fusion переезжает из глобального `fusion.json` (`enabled`) в память
сессии pi: runtime-отображение `sessionId → on/off` с восстановлением из истории
сессии (session-entries) на `session_start`. Разделяемая конфигурация не меняется
по составу; `enabled` исключается из схемы с миграцией «warn + ignore» (OQ-A).

## 2. Контракт состояния сессии

Новый модуль `extensions/pi-fusion/session-state.ts`:

```ts
type SessionActivation = { enabled: boolean; restoredFromHistory: boolean };
isSessionEnabled(sessionId: string | undefined): boolean;   // нет sessionId → false (FR-002/§7)
setSessionEnabled(sessionId: string, enabled: boolean): void;
restoreSessionFromHistory(sessionId: string): SessionActivation;
resetForTests(): void;
```

- Хранилище — `Map<string, boolean>` в памяти процесса расширения. Ключ —
  идентификатор сессии pi. Межпроцессного разделения нет и не требуется: каждый
  процесс pi обслуживает свои сессии.
- Персистенция решения — запись в историю сессии через механизм session-entries
  (по образцу pi-autoresearch: `pi.appendEntry('<ключ>.activation')` с записью
  значения и меткой времени). Ключ записи: `pi-fusion.activation`.
- Восстановление: на `session_start` сессии читаются её записи; последнее явное
  решение on/off восстанавливается. Нет записей → выключено (FR-002).
- **Верификация API (обязательный шаг реализации, не догадка):** точная поверхность
  API pi (получение `sessionId` из `ctx` обработчиков событий; подпись
  `appendEntry`; чтение записей истории при `session_start`/resume) сверяется с
  установленным pi (dist + docs) и с рабочим образцом
  `C:/Users/user/.pi/agent/git/github.com/fan92rus/pi-autoresearch` (его
  session-ID keyed runtime и восстановление активации). Расхождение с образцом
  фиксируется в отчёте задачи; автозапуск по признакам проекта из образца НЕ
  копируется (решение владельца 08:59).

## 3. Точки проводки (текущий код → новое)

| Место | Сейчас | Станет |
|---|---|---|
| `commands.ts` `turnFusion(on/off)` (:~208) | пишет `enabled` в глобальный `fusion.json` | меняет только session-state; пишет session-entry; сообщение «действует до конца сессии (включая resume/reload), другие сессии не затрагиваются» |
| `commands.ts` `showStatus` (:233–255) | читает глобальный `enabled` | показывает флаг текущей сессии + источник («память сессии» / «восстановлено из истории») |
| `commands.ts` `runFusionDelegate` | не проверяет `enabled` | проверяет флаг сессии самостоятельно; off → отказ «fusion выключен в этой сессии — включите /fusion on» (FR-004) |
| `index.ts` регистрация restrictions/guidance/`fusion_delegate` | замыкание на глобальный `enabled` (перечитывается) | замыкание на `isSessionEnabled(ctx.sessionId)`; обработчики получают ctx с идентификатором сессии (механика ctx — как в волне 6: ExtensionContext вторым аргументом; точное поле sessionId — по верификации §2) |
| `config.ts` / `config-bridge.ts` | `enabled` в defaults/snapshot/readFields/persist | поле исключено; чтение файла с `enabled` → предупреждение «поле enabled игнорируется: активация в памяти сессии (/fusion on|off)», файл НЕ перезаписывается при чтении (FR-005, OQ-A) |
| `config-ui.ts` | строка редактирования `enabled` в разделяемом конфиге | строка убрана из редактора разделяемой конфигурации; активация — только on/off текущей сессии |

## 4. Жизненный цикл сессии

1. `session_start(S)` → `restoreSessionFromHistory(S)`: последнее явное решение
   из истории сессии; нет записей → off. Новая сессия (включая `/fork`, OQ-B) →
   записей нет → off.
2. `/fusion on|off` в сессии S → `setSessionEnabled(S, v)` + session-entry.
   Другие сессии процесса не затрагиваются; файлы не пишутся.
3. resume/reload сессии S → повторный `session_start(S)` → восстановление.
4. tool_call / вызов `fusion_delegate` в сессии S → гейты и делегация читают
   `isSessionEnabled(S)`.
5. Headless (`pi -p`) и дочерние сессии (`PI_SUBAGENT_CHILD=1`): правила
   `isLeadSession` прежние (волна 4–8); при отсутствии идентификатора сессии у
   обработчика — консервативно «выключено» для активационных решений (гейт
   регистрации инструментов не срабатывает), поведение дочерних сессий не меняется.

## 5. Отвергнутые альтернативы

- `enabled` как глобальный дефолт для новых сессий — сохраняет глобальный источник
  истины, противоречит решению 11:24 («привязана к памяти сессии»); отвергнуто.
- Наследование решения при `/fork` — fork создаёт новую сессию; наследование
  smuggling'ом разделяемого состояния; отвергнуто (OQ-B, подтвердить владельцу).
- Хранение активации в `fusion.json` с ключом сессии — снова разделяемый файл,
  гонки между процессами; отвергнуто в пользу памяти процесса + истории сессии.

## 6. OQ

- **OQ-A (FR-005):** исключение `enabled` с миграцией «warn + ignore» —
  рекомендация. Альтернатива (сохранить поле как no-op без warn) хуже: молчаливое
  устаревшее поле в конфиге пользователя вводит в заблуждение.
- **OQ-B (FR-003):** `/fork` → новая сессия, старт off — рекомендация.

## 7. Тесты (TDD; hermetic)

- **Unit session-state:** set/get; отсутствие sessionId → false; восстановление
  из записей (последнее решение выигрывает); пустая история → off; изоляция двух
  sessionId.
- **Component commands:** on/off меняет только свою сессию (fake host с двумя
  sessionId); файловая система НЕ получает записей (fake fs — ноль вызовов записи);
  отказ `runFusionDelegate` при off с точным текстом; `showStatus` отражает
  флаг/источник; `/fusion config` не меняет активацию.
- **Component index/гейты:** session_start → tool_call: on-сессия получает
  restrictions/guidance/делегацию, off-сессия — нет; resume (повторный
  session_start с той же историей) восстанавливает on; разные сессии изолированы.
- **Config-миграция:** чтение fusion.json с `enabled: true` → warn, значение
  проигнорировано, файл не переписан; persist не пишет `enabled`; config-ui не
  показывает строку.
- Существующие пины, фиксирующие глобальный `enabled`, переписываются под
  сессионную модель (единственное разрешённое изменение пинов, FR-007); пины
  ролей/исключений/пула не меняются.

## 8. Развёртывание и живая приёмка

- Требуется перезапуск pi. После него ВСЕ сессии стартуют off — ожидаемо и
  согласовано (решение 08:59/11:24); в рабочей сессии владелец включает `/fusion on`.
- Живая приёмка (владелец или лид после перезапуска): (1) `/fusion on` в одной
  сессии не включает fusion в другой (проверка второй сессией: статус off,
  ограничения не действуют); (2) resume/reload восстанавливает решение; (3) `/fork`
  стартует off; (4) `fusion_delegate` при off отказывает с текстом FR-004; (5)
  глобальный `fusion.json` не содержит новых записей после on/off.
