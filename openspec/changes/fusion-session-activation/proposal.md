# Proposal: session-only активация fusion

## Status

ЧЕРНОВИК (требует независимого ревью и явного утверждения владельца; реализация — только после).

Решение владельца (2026-11-02 11:24, дословно по смыслу): «включение должно быть
привязано к памяти сессии, а общая конфигурация — пусть в целом остаётся как есть;
проектная конфигурация мыслима, только если тоже привязана к памяти сессии».
Ранее (2026-11-02 08:59): on/off — на каждую сессию отдельно, не глобально и не
на проект; автозапуск pi-autoresearch по признакам проекта не копировать.

## Motivation

Активный дефект (наблюдение сессии 2026-11-02): `/fusion on|off` (commands.ts)
пишет `enabled` в глобальный `~/.pi/agent/fusion.json`, а инструменты меняет
только в вызывающей сессии; `index.ts` перечитывает глобальный флаг для
restrictions/guidance. Следствие: другая сессия может оказаться ограниченной
без активного `fusion_delegate` — или сохранить инструмент после глобального
`off`. `runFusionDelegate` не проверяет `enabled` самостоятельно. Плюс принцип
владельца: состояние активации не должно разделяться между сессиями.

## What Changes

- Решение on/off хранится в памяти сессии (ключ — идентификатор сессии pi);
  глобальный `fusion.json` больше НЕ источник истины активации и НЕ пишется
  командами on/off.
- Новая сессия стартует выключенной; никаких автозапусков по признакам проекта.
- resume/reload восстанавливают последнее решение сессии из её истории;
  fork — новая сессия (OQ-B).
- Гейты (restrictions/guidance) и `fusion_delegate` читают сессионный флаг;
  `runFusionDelegate` проверяет его самостоятельно и отказывает с явным текстом,
  если сессия выключена.
- Общая конфигурация `fusion.json` (workerModels, таймауты, блок-листы) не
  меняется; поле `enabled` исключается из схемы с миграцией «warn + ignore»
  (OQ-A — рекомендация; вариант: оставить как дефолт — отвергается, см. design).

## Out of Scope

- Автозапуск по каталогу/проекту (решение владельца 2026-11-02 08:59 — нет).
- Проектная (project-local) конфигурация fusion — допустима только вместе с
  привязкой к памяти сессии; в это изменение не входит (может быть отдельным
  изменением по запросу владельца).
- Изменение схем ролей/отчётов/профилей волны 4–8 — не затрагивается.
- Изменение места/формата общей конфигурации `fusion.json`.

## Impact

- Код: `extensions/pi-fusion/commands.ts` (turnFusion/showStatus),
  `index.ts` (регистрация гейтов/инструментов), `config.ts`/`config-bridge.ts`
  (поле `enabled`), новый модуль session-state, `guidance.ts` (строка статуса).
- Совместимость: после перезапуска pi все сессии стартуют off; пользователю
  нужно включать fusion в каждой рабочей сессии (ожидаемое поведение по решению
  владельца).
- Тесты: новые unit/component-тесты session-state и пины команд/гейтов.
