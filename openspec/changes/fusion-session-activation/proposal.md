## Motivation

Активный дефект (наблюдение внешнее, подтверждено ревью 1.1 по коду): `/fusion
on|off` (commands.ts:209) пишет `enabled` в глобальный `~/.pi/agent/fusion.json`,
инструменты меняет только в вызывающей сессии; index.ts:200/:270 перечитывает
глобальный флаг; `runFusionDelegate` не проверяет `enabled`. Следствие: другая
сессия может оказаться ограниченной без активного `fusion_delegate` — или сохранить
инструмент после глобального `off`. Плюс принцип владельца: состояние активации не
разделяется между сессиями.

## What Changes

- Решение on/off хранится в памяти сессии (ключ — `ctx.sessionManager.getSessionId()`)
  с записью в историю сессии; глобальный `fusion.json` — не источник истины
  активации и не пишется командами on/off.
- Новая сессия (включая `/fork` и `/new`) стартует выключенной: записи активации
  несут владельца и применяются только своей сессией — унаследованные при ветвлении
  записи инертны (блокер ревью 1.1 закрыт на уровне спеки).
- `resume`/`reload` и `startup` с историей восстанавливают последнее решение
  сессии; никаких автозапусков по признакам проекта.
- Гейты (restrictions/guidance/реконсайл session_start) и `fusion_delegate` читают
  флаг сессии; `runFusionDelegate` (index.ts) проверяет его самостоятельно; при
  промахе кэша — ленивое восстановление до решения; ошибки восстановления —
  по-гейтно (мутации — отказ).
- Общая конфигурация не меняется по составу, кроме поля `enabled`: исключается из
  схемы с миграцией «warn once + ignore» (OQ-A).
- Headless — та же сессионная модель плюс явный способ включения на запуске:
  переменная окружения `PI_FUSION_ON` (решение владельца 2026-11-02 «для pi -p
  нужен способ включения»; OQ-C закрыт).

## Out of Scope

- Автозапуск по каталогу/проекту (решение владельца 08:59 — нет).
- Проектная (project-local) конфигурация fusion — только с привязкой к памяти
  сессии; отдельное изменение по запросу владельца.
- Схемы ролей/отчётов/профилей, исключения лида, пул, seam — не затрагиваются.
- Изменение места/формата общей конфигурации.

## Impact

- Код: `commands.ts` (turnFusion/showStatus/описания), `index.ts` (реконсайл
  session_start, `runFusionDelegate`-guard, registerFusionDelegate-тип,
  guidance-факты), `restrictions.ts` (сессионный шов `(ctx) => boolean`),
  `config.ts` / `config-bridge.ts` / `config-ui.ts` (исключение enabled,
  миграция), новый `session-state.ts`, `guidance.ts` (собственный тип фактов),
  README.md.
- Совместимость: после перезапуска pi новые сессии стартуют off (возобновляемые —
  восстанавливают своё решение); в рабочей сессии нужно `/fusion on`. Guidance в
  дочерних сессиях пропадает (намеренно: guidance — для лида).
- Тесты: перепись пинов глобального `enabled` (исчерпывающий перечень — design §7)
  + новые unit/component тесты session-state и проводки.
